<h1 align="center">KOTEacher</h1>
<p align="center"><b>KOTE</b>(코테) + <b>Teacher</b>. 내 컴퓨터에서 도는 AI 코치와 함께 푸는 코딩 테스트 연습 프로그램입니다.</p>

프로그래머스 90문제(Lv1\~5, 카카오·PCCP 기출 위주)와 알고리즘 개념 문서 35개가 들어 있습니다. 실행(⌘↵)하면 테스트가 돌고(상단 '자동 검사'를 켜면 손을 멈출 때마다), 틀린 곳이 있으면 코치가 그 줄 바로 아래에 말풍선으로 질문을 던집니다. 정답을 알려 주지 않고, 스스로 찾게 돕습니다.

- **판정은 테스트가 합니다.** 문제마다 예시와 히든 테스트(무작위 입력 수백 개)를 돌리고, 틀리면 가장 작은 반례를 찾아 보여 줍니다.
- **실전처럼도 풉니다.** 실전 모드를 켜면 자동 검사, 코치, 힌트가 꺼지고 예시 실행과 제출만 남습니다. 제출하면 맞힌 개수와 정확성 점수만 알려 줍니다.
- **코치는 질문만 합니다.** 한 군데만 고치면 되는 실수는 AI 없이 바로 찾아 줄을 짚고, 나머지는 gemma4가 실행 추적을 보고 원인 줄을 찾습니다. 답을 흘리지 않도록 걸러 냅니다.
- **기본은 내 컴퓨터 안에서 돕니다.** 코드와 질문을 인터넷으로 보내지 않습니다. 컴퓨터가 버거우면 외부 API(OpenAI, Claude, Gemini 등)를 골라 쓸 수도 있습니다. AI 없이도 문제 풀기, 테스트, 반례 찾기, 개념 문서는 쓸 수 있습니다.

## 설치

### 맥 (가장 쉬운 방법)

1. [Releases](https://github.com/Hong-Iron/KOTEacher/releases)에서 둘 중 하나를 받습니다.
   - **`KOTEacher-*-arm64.pkg` (추천)**: 더블클릭해 설치합니다. 설치 프로그램으로 깐 앱은 바로 열리고, 터미널 명령이 필요 없습니다.
   - **`KOTEacher-*-arm64.dmg`**: 열면 보이는 **KOTEacher 설치하고 열기**를 더블클릭합니다. 앱을 Applications 폴더에 복사하고, 인터넷에서 받은 파일에 붙는 표시를 지운 뒤 엽니다.
2. 이 앱은 Apple 공증을 받지 않아서, pkg나 **설치하고 열기**를 처음 열면 **"…을(를) 열지 않음 · Apple은 … 악성 코드가 없음을 확인할 수 없습니다"** 창이 뜹니다. 파란 **휴지통으로 이동**이 아니라 **완료**를 누릅니다. 그다음 **시스템 설정 → 개인정보 보호 및 보안**의 맨 아래 보안 항목에서 **그래도 열기**를 누르고, 암호를 넣은 뒤 다시 엽니다. (macOS 15부터는 오른쪽 클릭 → 열기로는 넘어가지 않습니다.)

   dmg에서 앱을 직접 Applications로 끌어다 놓았다면, 처음 열 때 **"손상되었기 때문에 열 수 없습니다"**가 뜰 수 있습니다. 파일이 망가진 것이 아닙니다. 휴지통으로 옮기지 말고 **취소**를 누른 뒤, **설치하고 열기**를 더블클릭하거나 터미널(응용 프로그램 → 유틸리티 → 터미널)에 아래 한 줄을 붙여 넣고 Enter를 누릅니다. 인터넷에서 받은 파일에 붙는 표시를 지우는 명령입니다.

   ```bash
   xattr -dr com.apple.quarantine /Applications/KOTEacher.app
   ```
3. 앱을 열면 코치 준비 창이 뜨고 코치 모델(5.2GB)을 바로 받기 시작합니다. Ollama가 꺼져 있으면 켜고, 없으면 창의 **Ollama 설치하고 모델 받기** 버튼 하나로 [Ollama](https://ollama.com/download) 설치까지 합니다. 창을 닫아도 받기는 계속되고, 위쪽에 몇 %인지 보입니다. 컴퓨터가 버거우면 Ollama 없이 [외부 API](#다른-모델과-외부-api) 키로 써도 됩니다.

애플 실리콘(M1 이후) 맥용입니다. 인텔 맥은 아래 한 줄 설치를 써 주세요. 한 줄 설치로 깔면 이 경고 자체가 뜨지 않습니다.

### Windows (가장 쉬운 방법)

1. [Releases](https://github.com/Hong-Iron/KOTEacher/releases)에서 `KOTEacher-*-Setup.exe`를 받아 실행합니다. 관리자 권한 없이 내 계정에 설치되고 시작 메뉴에 KOTEacher가 생깁니다. 설치 없이 쓰려면 `KOTEacher-*-windows-x64.zip`을 풀고 `KOTEacher.exe`를 실행합니다.
2. "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행**을 누릅니다(서명하지 않은 프로그램이라 뜹니다).
3. [Ollama](https://ollama.com/download)를 설치해 둡니다. 앱을 열면 코치 준비 창이 뜨고, Ollama가 꺼져 있으면 켠 뒤 코치 모델(5.2GB)을 바로 받기 시작합니다. 컴퓨터가 버거우면 Ollama 없이 [외부 API](#다른-모델과-외부-api) 키로 써도 됩니다.

Windows 10/11 64비트용입니다. 화면은 Windows에 들어 있는 WebView2로 그립니다.

### 한 줄 설치 (맥, Linux)

```bash
curl -fsSL https://raw.githubusercontent.com/Hong-Iron/KOTEacher/main/install.sh | bash
```

파이썬 확인 → 앱 내려받기(`~/KOTEacher`) → 패키지 설치 → 문제 팩 만들기 → Ollama 설치 → 메모리에 맞는 모델 받기 → 앱 아이콘 만들기를 차례로 합니다. 다시 실행하면 업데이트됩니다.

### 한 줄 설치 (Windows, PowerShell, 소스로 설치)

```powershell
irm https://raw.githubusercontent.com/Hong-Iron/KOTEacher/main/install.ps1 | iex
```

winget으로 파이썬, git, Ollama를 설치하고 시작 메뉴에 KOTEacher를 넣습니다. 아직 Windows 실기기에서 시험하지 못했습니다. 막히면 위의 설치 프로그램을 쓰거나 이슈로 알려 주세요.

### 직접 설치

```bash
git clone https://github.com/Hong-Iron/KOTEacher.git && cd KOTEacher
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python tools/build_packs.py     # 문제 팩 (약 20초)
.venv/bin/python -m koteacher             # 실행
```

파이썬 3.10 이상이 필요합니다. Linux는 창을 띄우는 데 GTK WebKit이 필요합니다(`sudo apt install python3-gi gir1.2-webkit2-4.1`).

## 코치 모델

| 선택 | 모델 | 크기 | 특징 |
|---|---|---|---|
| 자동 · 속도 우선 (기본) | `ghcr.io/hong-iron/gemma4-e4b-text` | 5.2GB | 응답이 약 2배 빠르고 메모리를 덜 씁니다 |
| 정확도 우선 | `gemma4:12b-it-qat` | 7.2GB | 더 큰 모델. 메모리 16GB 이상에서 쓰세요 |
| Ministral 3 8B | `hf.co/mistralai/Ministral-3-8B-Instruct-2512-GGUF:Q4_K_M` | 6.1GB | Mistral AI 모델. 반례 값을 넣어 구체적으로 묻지만, 버그 줄은 e4b보다 덜 맞히고(7/12) 응답이 3배쯤 느립니다 |

코치의 지시문, 온도, 대화 구조, 말 다듬기는 모델 계열마다 따로 둡니다(`koteacher/coach.py`의 `PROFILES`). 지금 쓰는 모델 이름으로 저절로 고릅니다. gemma는 기본 지시문, Ministral은 Mistral 권장(쓰임새를 시스템 프롬프트에 분명히, 온도 0.1 아래)에 맞춘 지시문, Qwen 계열(OmniCoder 포함)은 Qwen 버릇에 맞춘 지시문을 씁니다. 어떤 모델이든 코치 말에 "A 대신 B"나 "~바꿔야 합니다"처럼 고칠 곳을 대놓고 말하면 정해진 문장으로 바꿉니다.

같은 맥(M3 16GB)에서 버그를 두 군데 심은 12문제로 견주어 보니, e4b는 응답이 약 5초(12B 약 9초)에 끝났고 버그 줄 적중도 9/12로 12B(6/12)보다 낮지 않았습니다. `ghcr.io/hong-iron/gemma4-e4b-text`는 `gemma4:e4b-it-qat`에서 그림을 읽는 부분(약 1GB)만 뺀 것으로, 이 저장소의 GitHub 패키지에서 계정 없이 받습니다. 코치는 글만 주고받으므로 답은 원래 모델과 같고, 받을 양만 줄어듭니다. 이미 `gemma4:e4b-it-qat`를 받아 두었다면 그대로 그것을 씁니다.

받는 동안 받은 양, 속도, 남은 시간, 받는 곳(GitHub 또는 Ollama 서버)이 보입니다. 기본 모델은 GitHub에서 받다가 끊기면 받던 데서 이어 받으며 3번까지 다시 시도하고, 그래도 안 될 때만 Ollama 서버에서 원래 모델을 받습니다. 정확도 우선(12B)은 Ollama 서버에서, Ministral은 Hugging Face에서 받습니다. Ollama 서버는 네트워크에 따라 매우 느릴 때가 있습니다(초당 0.2MB를 잰 적이 있습니다). 코치 상태(상단 오른쪽)를 눌러 바꿀 수 있습니다. 앱을 켜면 모델을 미리 불러오고, 끄면 내립니다(앱이 불러온 경우만).

### 다른 모델과 외부 API

코치 상태(상단 오른쪽)를 누르면 코치 설정이 열립니다.

- **내 컴퓨터 (Ollama) → 다른 모델**: Ollama에 있는 모델을 이름으로 고릅니다(예: `qwen3:8b`). 없으면 받습니다.
- **외부 API**: OpenAI, Anthropic(Claude), Google Gemini, OpenRouter, Groq, 그리고 OpenAI 호환 서버(LM Studio, vLLM 등)를 쓸 수 있습니다. 내 API 키와 모델 이름을 넣고 '연결 확인' 뒤 저장합니다. '목록 불러오기'를 누르면 그 회사에서 쓸 수 있는 모델 이름이 나옵니다.

외부 API를 쓰면 지금 푸는 문제, 내 코드, 테스트 결과, 질문이 그 회사 서버로 보내지고, 요금은 내 계정에 나옵니다. 키는 앱 설정 파일(맥 `~/Library/Application Support/KOTEacher/settings.json`, 윈도 `%APPDATA%\KOTEacher\settings.json`)에만 저장됩니다. `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` 같은 환경 변수가 있으면 그것도 씁니다. 코치 말은 gemma4에 맞춰 다듬었으므로, 다른 모델은 말투나 정확도가 다를 수 있습니다. 생각(추론)하는 모델은 느리므로 빠르고 작은 모델을 추천합니다.

## 쓰는 법

| 화면 | 하는 일 |
|---|---|
| 문제 | 레벨별 90문제 |
| 로드맵 | 단원별 개념 표. 개념을 누르면 개념 문서, 문제를 누르면 바로 풀기. 문제 옆 점: 초록 통과, 노랑 힌트로 통과, 빨강 시도 |
| 풀기 | 왼쪽 문서 창(문제 + 개념 문서 탭) · 오른쪽 코드 창. 경계선을 끌어 너비를 바꾸고, 양쪽을 접을 수 있습니다 |
| 풀이 기록 | 지난 시도의 코드, 실행 흐름, 코치의 말. 그 코드로 다시 열 수 있습니다 |
| 오답 노트 | 틀렸다가 고친 순간이 자동으로 쌓입니다. 고친 차이, 걸린 시간, 내 메모. 누르면 그 문제로 갑니다 |
| 프로필 | GitHub 잔디처럼 지난 1년 동안 날마다 코드를 실행한 문제 수를 칸 색으로 보여 줍니다. 지금 연속·가장 긴 연속 일수, 통과한 문제, 레벨별 진도. 칸을 누르면 그날 푼 문제가 나옵니다. 홈의 프로필 버튼 옆 숫자는 연속 일수입니다(오늘 풀었으면 초록) |
| 정보 | 홈 왼쪽 위의 로고나 KOTEacher를 누르면 열립니다. 버전, 코치 모델, 내 기록이 있는 폴더, 새 버전 확인 |

- **힌트 사다리**: 작은 예로 손으로 풀기 → 핵심 아이디어 → 코드 흐름 → 풀이 보기. 두 번째 힌트부터 그 시도는 오답으로 기록됩니다.
- **자동 검사**: 상단 '자동 검사'를 켜면 손을 멈추고 2.7초 뒤 저절로 검사합니다. 기본은 꺼져 있어서 실행(⌘↵)할 때만 검사합니다. 자동 검사가 도는 중에 실행을 누르면 그 검사를 끊고 바로 실행합니다.
- **코치 말수**: 조용히(물을 때만) · 보통(테스트로 확인된 문제만 먼저) · 적극(추정과 속도 걱정까지).
- **출력**: 아래 창의 '출력' 탭에 print한 내용이 나옵니다. 출력 탭을 보면서 실행하면 그 탭에 머뭅니다. 문법 오류로 돌지 못하면 지난 출력을 남겨 두고, 오류나 시간 초과로 멈추면 멈추기 전까지 print한 것을 보여 줍니다. 아래 창은 위 테두리를 끌어 높이를 바꿉니다.
- **함수 밖 코드**: 맨 아래에서 직접 부른 함수 같은 코드는 2초 안에 끝나야 합니다. 넘으면 어느 줄에서 부른 코드가 멈췄는지 알려 줍니다.
- **실전 모드**: 상단의 '실전'을 켜면 실제 코딩 테스트처럼 풉니다. 자동 검사, 코치, 힌트가 꺼집니다. 예시 실행(⌘↵)은 입출력 예만 돌리고, 제출(⌘⇧↵)은 히든 테스트를 모두 돌려 맞힌 개수와 정확성 점수만 보여 줍니다. 반례는 '실전 끄고 반례 보기'를 눌러야 보입니다. 반례나 코치를 보지 않고 제출로 통과하면 풀이 기록에 '실전 통과'로 남습니다. 실전 버튼 옆에서 제한 시간(20\~120분)을 고르면 남은 시간이 보이고, 시간이 끝나면 마지막 코드로 자동 제출한 뒤 편집을 잠급니다.
- **처음부터**: 아래 패널 오른쪽의 '처음부터'를 누르면 지금 코드를 풀이 기록에 저장하고 빈 틀로 새로 시작합니다. 저장한 코드는 '풀이 기록' 탭에서 다시 불러올 수 있습니다. 이미 연 힌트와 본 풀이는 새 시도에도 남습니다. 지난 코드를 이어 쓸 때(문제를 다시 열 때, 지난 코드를 불러올 때)도 그 코드를 쓸 때 받은 도움이 함께 남아서, 그 코드로 통과하면 '힌트로 통과'로 기록됩니다. 힌트 없이 다시 통과하려면 홈의 '다시 풀기'로 엽니다.
- **오류 밑줄**: 타이핑하는 동안 정의되지 않은 이름(빨강)과 쓰지 않는 import·변수(노랑)에 밑줄이 그어집니다. 실전 모드에서는 꺼집니다.
- **다시 풀기와 추천**: 홈 위쪽에 틀렸거나 힌트로 넘긴 문제(오래된 것 먼저)와, 자주 틀린 개념의 안 푼 문제가 뜹니다. '다시 풀기'는 지난 코드 없이 빈 틀로 엽니다. 오답 노트의 각 기록에도 '다시 풀기'가 있습니다.
- **코드 골라 묻기**: 편집기에서 코드를 드래그하면 '코치에게 묻기'가 뜹니다(⌘I, 오른쪽 클릭 메뉴). '무슨 일을 해?', '값을 따라가 줘', '틀릴 만한 곳?'을 누르거나 직접 물으면, 고른 줄 바로 아래에 답이 달립니다. 정답 코드는 알려 주지 않고, 실전 모드에서는 꺼집니다.
- **예제 코드 묻기**: 코치에게 "deque 쓰는 법 보여 줘"처럼 물으면 작은 일반 예제를 실행해 확인한 뒤 결과와 함께 보여 줍니다. "BFS 예제" 같은 알고리즘 틀은 검증된 개념 코드를 접어서 보여 주고, 펼치면 힌트 1개로 기록합니다. 정답·고친 코드는 보여 주지 않고 힌트 사다리로 안내합니다.
- **문서에서 골라 묻기**: 개념 문서나 문제문에서 글을 드래그하면 "코치에게 묻기"가 뜹니다. 물은 곳에는 형광펜이 남고, 문단 아래에 질문과 답이 기록됩니다. 문서 속 예제 코드와 개념 코드에서도 같은 방법으로 물을 수 있고, 답은 고른 줄 바로 아래에 달립니다.

| 단축키 | 동작 |
|---|---|
| ⌘↵ | 실행 (실전 모드에서는 예시 실행) |
| ⌘⇧↵ | 제출 (실전 모드) |
| ⌘I | 고른 코드를 코치에게 묻기 |
| ⌘K | 전체 검색 (문제, 개념, 문서 본문, 내 질문, 오답 기록) |
| ⌘B / ⌘⇧B | 문서 창 / 코드 창 접기 |
| Esc | 검색 창, 묻기 창, 정보 창 닫기 |

Windows에서는 ⌘ 대신 Ctrl을 누릅니다.

## 업데이트와 내 기록

- 새 버전은 정보 창의 **새 버전 확인**으로 알 수 있습니다. [Releases](https://github.com/Hong-Iron/KOTEacher/releases)에서 새 설치 파일을 받아 덮어 설치하면 됩니다. 한 줄 설치로 깔았다면 같은 명령을 다시 실행합니다.
- 풀이 기록, 오답 노트, 문서에 남긴 질문, 설정은 앱과 따로 아래 폴더에 저장되므로 업데이트해도 그대로 남습니다. 처음부터 다시 하려면 이 폴더를 지웁니다.
  - 맥: `~/Library/Application Support/KOTEacher`
  - Windows: `%APPDATA%\KOTEacher`
  - Linux: `~/.local/share/KOTEacher`

## 자주 묻는 것

- **코치가 느리거나 컴퓨터가 버벅입니다.** 코치 설정에서 '속도 우선(gemma4 e4b)'을 고르세요. 메모리가 16GB보다 작으면 외부 API를 쓰는 편이 낫습니다. 테스트와 반례 찾기는 AI 없이 돌아가므로 코치를 꺼도(조용히) 문제는 풀 수 있습니다.
- **외부 API에서 '키가 맞지 않습니다'가 뜹니다.** 키를 다시 붙여 넣고 **연결 확인**을 눌러 보세요. 모델 이름은 **목록 불러오기**로 고르면 오타가 없습니다.
- **어떤 파이썬 기능을 쓸 수 있나요?** 표준 라이브러리(heapq, bisect, collections, itertools, math 등)를 쓸 수 있습니다. 프로그래머스처럼 `solution` 함수를 채우면 됩니다.

- `content/`의 개념 문서와 풀이는 Obsidian 볼트의 알고리즘 노트에서 옮긴 것입니다(블로그 [Studies · 알고리즘](https://hong-iron.github.io/Hongs_Blog/studies/algorithms/)과 같은 내용).
- 문제 설명은 프로그래머스 원문을 줄여 쓴 것이고, 문제의 저작권은 프로그래머스와 출제처에 있습니다. 원문은 각 문제의 링크로 볼 수 있습니다.
- 개념 문서의 수식은 KaTeX, 그림은 Mermaid로 그립니다. 편집기는 Monaco입니다(각 라이선스는 `ui/vendor/`에 있습니다).

## 만드는 사람용

| 파일 | 하는 일 |
|---|---|
| `koteacher/capture.py`, `packs.py` | 풀이 코드의 검사 블록을 돌리며 `solution` 호출(입력, 기준 답)을 기록해 문제 팩을 만듭니다 |
| `koteacher/harness.py`, `runner.py` | 별도 프로세스에서 학생 코드 검사: 예시, 히든 테스트(가장 작은 반례), 변이 탐색, 실행 추적 |
| `koteacher/coach.py` | 코치 파이프라인: 사실 → 진단(수리·규칙·AI) → 말하기 → 유출 검사 → 전달 규칙 |
| `koteacher/render.py`, `vault.py` | Obsidian 마크다운(콜아웃, 수식, 위키링크) → 화면 |
| `koteacher/api.py`, `app.py`, `ui/` | 화면과 창 (pywebview, 서버 없음) |
| `eval/` | 코치 평가: 모범 풀이에 버그를 심은 시험지(1군데 258개, 2군데 81개) |
| `tools/sync_content.py` | 볼트 → `content/` (수업 자료 언급과 원본 오류 상자는 뺍니다) |
| `tools/build_mac.py` | 맥 앱과 dmg 만들기 (PyInstaller) |
| `tools/build_win.py`, `tools/KOTEacher.iss` | 윈도 실행 파일과 설치 프로그램 (PyInstaller, Inno Setup). GitHub Actions `build-windows`가 돌립니다 |
| `docs/design.html` | 처음 설계서 |

코치 평가 결과(맥북 에어 M3 16GB, gemma4 12B): 한 군데 버그는 AI 없이 94%를 고쳐 버그 줄을 약 96% 맞혔고, 두 군데 버그의 AI 진단은 버그 줄을 77% 맞혔습니다. 답 유출은 0건이었습니다.

### 속도

같은 맥에서 잰 값입니다. 프롬프트를 처음 읽는 속도는 초당 약 80\~100토큰, 생성은 초당 9\~11토큰이고, 오래 돌리면 발열로 조금씩 느려집니다. Ollama 설정(flash attention, KV 캐시 형식)을 바꿔도 차이는 발열로 생기는 차이보다 작았으므로 Ollama 기본값을 그대로 씁니다.

그래서 앱 쪽에서 기다림을 줄입니다.
- 한 군데 실수는 AI 없이 0.1초 안에 줄을 짚고 정해진 문장을 먼저 보여 준 뒤, AI 문장이 준비되면 그 자리를 흘려 바꿉니다.
- 학생에게 할 말을 JSON 앞쪽에 두어 먼저 흘러나오게 합니다.
- 문제를 열 때와 타이핑이 멈출 때 규칙·문제·코드를 미리 읽혀 둡니다. gemma4는 일부 층이 최근 1,024토큰만 보는 구조라서 Ollama가 저장해 둔 기준점에서만 이어 쓸 수 있습니다. 그래서 문제·코드와 증거를 서로 다른 말로 나눠 보냅니다. 이렇게 하면 코치의 첫 글자가 약 35% 빨라집니다(6.4초 → 3.9초).
